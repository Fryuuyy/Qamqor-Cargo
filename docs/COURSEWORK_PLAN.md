# Курстық жұмыстың ұсынылатын құрылымы

Тақырып: «Жүк тасымалдауға тапсырыс беру веб-қосымшасын жасау».

## КІРІСПЕ
Жүк тасымалдау қызметін ұйымдастыру кезінде тапсырыс беруші тасымалдау бағытын, жүк түрін, салмағын және жеткізу күнін көрсетуі керек. Өтінімдерді қағаз немесе мессенджер арқылы қабылдау кезінде мәліметтерді іздеу, өтінім мәртебесін бақылау және тапсырыс тарихын сақтау қиындауы мүмкін. Осы оқу жобасында өтінімді веб-интерфейс арқылы жіберу және оны әкімші тарапынан басқару тәсілі қарастырылады.

**Жұмыстың мақсаты:** Python және FastAPI технологияларын пайдаланып, жүк тасымалдауға өтінім қабылдайтын және өтінім мәртебесін басқаратын веб-қосымша әзірлеу.

**Міндеттері:**
1. Жүк тасымалдау саласындағы негізгі пайдаланушы сценарийлерін талдау.
2. Веб-қосымшаның функционалдық талаптарын анықтау.
3. Дерекқордың реляциялық моделін жобалау.
4. FastAPI негізінде серверлік API әзірлеу.
5. Пайдаланушыны тіркеу және авторизациялау механизмін жасау.
6. Өтінімдерді құру, қарау және мәртебесін өзгерту функцияларын іске асыру.
7. HTML, CSS және JavaScript көмегімен интерфейс әзірлеу.
8. Негізгі сценарийлерді тестілеу.

**Зерттеу нысаны:** жүк тасымалдауға өтінім беру және оны өңдеу үдерісі.

**Зерттеу пәні:** веб-интерфейс, REST API, реляциялық дерекқор және пайдаланушы құқықтарын тексеру тәсілдері.

## 1 ПӘНДІК САЛА МЕН ТЕХНОЛОГИЯЛАРҒА ШОЛУ
### 1.1 Жүк тасымалдау үдерісінің сипаттамасы
Тапсырыс беруші бастапқы және соңғы қаланы, жүк түрін, салмағын, тасымалдау күнін және байланыс телефонын көрсетеді. Әкімші өтінімді қарап, оның мәртебесін өзгертеді. Жобада тасымалдау бағасын автоматты есептеу қарастырылмайды.

### 1.2 Ұқсас жүйелерді талдау
Салыстыру үшін жүк тасымалдау қызметтерінің өтінім формаларын, бағыт енгізу тәсілдерін және тапсырыс мәртебесін көрсету мүмкіндіктерін зерттеу ұсынылады. Нақты сервистерді және олардың қазіргі функцияларын дереккөздермен тексермей тұрып ойдан жазуға болмайды.

### 1.3 Технологияларды таңдау
Python серверлік логиканы іске асыруға, FastAPI HTTP API құруға, SQLAlchemy дерекқормен жұмыс істеуге, Pydantic кіріс деректерін тексеруге қолданылады. SQLite оқу жобасын жергілікті компьютерде іске қосуға ыңғайлы. HTML, CSS және JavaScript интерфейстің құрылымын, стилін және интерактивті әрекеттерін қамтамасыз етеді.

## 2 ЖҮЙЕНІ ЖОБАЛАУ
### 2.1 Функционалдық талаптар
- Клиентті тіркеу және жүйеге кіргізу.
- Тасымалдауға өтінім құру.
- Өз өтінімдерінің тізімін көрсету.
- Рұқсат етілген кезеңде өтінімді тоқтату.
- Әкімшіге барлық өтінімдерді көрсету.
- Әкімшіге өтінім мәртебесін өзгерту.

### 2.2 Рөлдер
Жүйеде екі рөл бар: `customer` және `admin`. Клиент тек өз өтінімдерін басқарады. Әкімші барлық өтінімдерді көреді және олардың мәртебесін өзгертеді.

### 2.3 Дерекқор құрылымы
Дерекқор екі негізгі кестеден тұрады: `users` және `transport_requests`. Бір пайдаланушы бірнеше өтінім бере алады. Өтінім пайдаланушының сыртқы кілтімен байланысады.

### 2.4 ER-диаграмма
Диаграмма `docs/ER_DIAGRAM.md` файлында Mermaid форматында берілген.

### 2.5 API эндпоинттері
Маршруттар `docs/API.md` файлында әдісі, мекенжайы, рұқсаты және сұраныс мысалдарымен көрсетілген.

### 2.6 Деректерді валидациялау
Pydantic схемалары қалалардың, жүк түрінің, телефонның, салмақтың және күннің мәндерін тексереді. Салмақ нөлден үлкен және 50 000 кг-нан аспауы керек. Бастапқы және соңғы қала бірдей болмауы керек.

## 3 ВЕБ-ҚОСЫМШАНЫ ІСКЕ АСЫРУ
### 3.1 Файлдық архитектура
Жобаның файлдық құрылымы `README.md` ішінде берілген. Серверлік логика `app` бумасында, тесттер `tests` бумасында, техникалық құжаттама `docs` бумасында орналасады.

### 3.2 FastAPI сервері
`app/main.py` FastAPI қосымшасын жасайды, маршруттарды тіркейді, статикалық файлдарды және HTML шаблонын береді.

### 3.3 Дерекқормен байланыс
`app/database.py` SQLAlchemy engine, session және Base класын анықтайды. Әр HTTP сұранысына жеке дерекқор сессиясы беріледі.

### 3.4 Тіркелу және авторизация
Құпиясөз Argon2 арқылы хештеледі. Кіруден кейін сервер HS256 алгоритмімен қол қойылған JWT қайтарады. Қорғалған маршруттар токенді тексереді.

### 3.5 Өтінімдерді басқару
Клиент өтінім жасайды, өзінің өтінімдерін қарайды және рұқсат етілген жағдайда тоқтатады. Әкімші мәртебені бекітілген ауысу ережелері бойынша өзгертеді.

### 3.6 Пайдаланушы интерфейсі
HTML бет құрылымын, CSS визуалды стильді, JavaScript API сұраныстарын және интерфейсті жаңартуды орындайды. Бет Jinja2 арқылы FastAPI серверінен беріледі.

### 3.7 Әкімшілік панель
Әкімші панелі барлық өтінімдерді көрсетеді. Әкімші өтінім мәртебесін таңдап, қосымша ескерту енгізе алады.

## 4 ТЕСТІЛЕУ
Тіркелу, қайталанған email, өтінім құру, өзге пайдаланушы өтінімін оқу әрекеті, әкімші рұқсаты, салмақ валидациясы, өтінімді тоқтату және мәртебе ауысуы тексеріледі. Нақты орындалған тест нәтижелері `docs/TEST_REPORT.md` файлында тіркелген.

## ҚОРЫТЫНДЫ
Жоба нәтижесінде клиентке жүк тасымалдау өтінімін жіберуге, ал әкімшіге өтінімдерді қарап, олардың мәртебесін басқаруға мүмкіндік беретін оқу веб-қосымшасы әзірленді. Жүйе Python, FastAPI, SQLite, SQLAlchemy, Pydantic және HTML/CSS/JavaScript технологияларына негізделген.

## ЖОБАНЫҢ ШЕКТЕУЛЕРІ
Жоба нақты тасымалдаушы компанияның жұмысын толық автоматтандырмайды. Онлайн төлем, GPS бақылау, жүргізушілерді бөлу, автоматты баға есептеу және хабарлама сервистері іске асырылмаған. Бұл шектеулер оқу жобасының көлемін негізді деңгейде ұстайды.
